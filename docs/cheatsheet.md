# Шпаргалка: как запускать

Один экран. Подробности в [HOWTO](HOWTO.md).

## Вам, разработчику, нужна одна команда

```sh
cd tdc-runner
./run_local.sh <имя набора> --repo <ваш репозиторий>
```

Всё. Это тот же код, который потом запустит сервер. Если прошло у вас, пройдёт
и там.

Проверить файлы, не поднимая контейнеры:

```sh
python3 -m tdc validate --repo <ваш репозиторий>
```

## Когда нужны ключи

| Ключ | Когда |
|---|---|
| `--artifacts <каталог>` | набор берёт файлы из сборки, то есть в `test_cfg.xml` есть `<inputs>` с `<artifact>` |
| `--secrets <каталог>` | в `test_cfg.xml` есть `<secrets>` |
| `--out <каталог>` | отчёты нужны не в `.tdc-out` внутри репозитория |
| `--dry-run` | проверить всю подготовку, но не запускать контейнеры |

## Где смотреть результат

```
<ваш репозиторий>/.tdc-out/reports/<набор>/
    tests/      результаты тестов
    coverage/   покрытие
    _infra/     логи контейнеров
```

Упало: открывайте `_infra/compose-logs.txt`. Он пишется всегда.

## Три частые ошибки

| Что видите | Что делать |
|---|---|
| `набор ... не найден`, ниже список доступных | опечатка в имени. Возьмите имя из списка |
| `permission denied ... docker.sock` | вы не в группе `docker`. Либо `sudo`, либо `sudo usermod -aG docker $USER` и перелогиниться |
| `reports.zero_matches` | тесты не положили отчёт в `/test/output`, или путь в `test_cfg.xml` не совпал |

## Чего делать не надо

Не запускайте `docker compose up` руками поверх своего файла. Система
добавляет к нему ограничения, изоляцию и уборку. Запущенное вручную не уберётся
за собой и займёт машину.

Не правьте файлы в `.tdc-out`. Каталог полностью пересоздаётся при каждом
запуске.
